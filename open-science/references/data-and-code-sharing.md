# Data and Code Sharing

The goal of sharing is not merely to upload files. It is to make research artifacts findable, interpretable, reusable, and properly attributable.

## Before sharing, verify rights and ethics

Check:

- participant consent and privacy,
- data-use agreements,
- third-party licenses,
- embargoes,
- repository requirements,
- sensitive or dual-use implications where relevant.

Do not treat publicly accessible data as automatically unrestricted for every use.

## Share the version that supports the paper

For data, preserve the dataset or documented transformation state used for analysis when feasible.

For code, tag or archive the version that produced the reported results. A live repository can evolve after publication; the scientific record needs a stable reference point.

## Make artifacts citable

Use persistent identifiers where possible. Provide citation instructions for datasets and software, and cite external data you reuse rather than only citing the paper that first mentioned it.

## Include reuse context

For data, provide metadata, provenance, units, schemas, and preprocessing history.

For code, provide environment/dependency information, example execution, expected inputs/outputs, and a license.

## Distinguish availability from reproducibility

A public repository containing source code is not enough if users cannot identify the correct version, reconstruct dependencies, obtain the required data, or reproduce the command that generated a result.
